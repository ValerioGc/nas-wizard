<h2 id="os_configuration">2. System configuration and starting the wizard</h2>

<p>Use the local administrator account <code>nas</code> with <code>sudo</code> access. The launcher
runs as the separate <code>nas-os</code> service user, and the gateway uses a dynamic systemd user.
The wizard creates a third local user for the interface's terminal, without a password or
<code>sudo</code>. Choose a name different from existing machine accounts.</p>

<h3 id="entry_script">1. Entry script</h3>
<p>Copy the package and checksum to the NAS, verify the archive, extract it into its own directory,
and run the entry script. This is the only installation command required:</p>

```bash
sha256sum -c nas-wizard-<version>-linux-x64.tar.gz.sha256
mkdir nas-wizard
tar -xzf nas-wizard-<version>-linux-x64.tar.gz -C nas-wizard
cd nas-wizard
./install.sh --dry-run
sudo ./install.sh
```

<p>The script checks Debian 13, LUKS encryption for the system, <code>/etc</code>,
<code>/var/lib</code>, and swap, and the presence of TPM 2.0. Missing protection produces a warning
and installation continues; Chapter 1 explains the implications. It then runs the pre-wizard tasks
(<code>packages/pre_wizard</code>, including operating-system configuration), checks the wizard
version, and starts the wizard. It requires no input: enter the token in the browser. The script
prints the browser address and follows progress until completion. Closing the terminal does not
stop the wizard, which runs as a systemd unit; use <code>journalctl -u nas-wizard -f</code> to follow
it again. The wizard runs from <code>/usr/local/lib/nas-wizard</code>. At completion it empties the
extracted directory, keeping only <code>uninstall.sh</code>, and copies the manuals to the newly
created terminal user's home.</p>

<h3 id="system_packages">2. System packages</h3>
<p>Operating-system configuration (<code>packages/os_configuration</code>) installs missing
<code>polkitd</code>, <code>nftables</code>, <code>network-manager</code>, <code>wpasupplicant</code>,
<code>wireless-regdb</code>, <code>parted</code>, <code>e2fsprogs</code>, <code>smartmontools</code>,
and <code>cryptsetup</code> without recommended packages. It records actual additions so removal
only removes those packages. NetworkManager does not take over interfaces already declared in
<code>/etc/network/interfaces</code>, preserving an existing SSH connection.</p>
<p>Existing packages, including ModemManager, BlueZ, and cron, are preserved. The original hostname,
network and DNS configuration, Samba configuration, and service states are saved before changes.
Removal and reset reuse this initial backup. Debian package upgrades remain allowed and are not
reversed. Older installations without this backup require recovery of their original configuration.
Without a Wi-Fi adapter, <code>wpa_supplicant</code> stays disabled. The check runs at each boot;
connecting an adapter later, including while the NAS is running, enables it immediately.</p>

<h3 id="screen">Connected display</h3>
<p>On a machine with video output, setup also installs <code>cog</code>, a browser that renders
directly to a monitor without a desktop environment. The display watcher is installed disabled.
Enable it explicitly when a local interface is wanted:</p>

```bash
sudo systemctl enable --now nas-os-screen.service
```

<p>With the watcher enabled, connect an HDMI, DisplayPort, DVI, or VGA monitor with a keyboard and
mouse. After a short wait, it shows the wizard until setup is complete, then the NAS sign-in page.
Sign-in requires the account password but no device certificate, even when mTLS is enabled.
The browser uses approximately 150-250 MB of memory and runs only while a monitor is connected.
After 10 minutes without keyboard or mouse input (adjustable in Settings > Power), the screen
turns off and the browser stops. Input wakes it and requires sign-in again.</p>
<p>The text console remains available. <kbd>Ctrl</kbd>+<kbd>Alt</kbd>+<kbd>F2</kbd> through
<kbd>F6</kbd> stops the browser and shows console login; <kbd>Ctrl</kbd>+<kbd>Alt</kbd>+<kbd>F1</kbd>
returns to the interface. For a virtual machine, send these combinations through the viewer's
menu so the host does not intercept them.</p>

<h3 id="base_firewall">3. Base firewall</h3>
<p>The same setup stage installs and immediately enables <code>nas-os-base-firewall.service</code>.
The <code>nas_base</code> table denies input, output, and forwarding by default. It allows TCP 80
for the wizard and gateway, gateway HTTPS on TCP 443, SSH on TCP 22 from private and link-local
addresses, and the protocols needed for DNS, NTP, DHCP, and ICMP. System updates, the wizard,
launcher, and authorized applications can use outbound HTTP and HTTPS. Other ports remain closed.
The loopback display port, TCP 8081, is reserved for its browser.</p>
<p><strong>SSH sessions from public addresses are interrupted.</strong> Verify private-network or
local-console access first. Settings > Access applies an additional allowed-address filter to
incoming requests.</p>

```bash
sudo nft list table inet nas_base
sudo systemctl status nas-os-base-firewall
```

<h3 id="wizard_token">4. Wizard version</h3>
<p>The entry script asks GitHub whether a newer wizard exists. If so, it downloads that release
into <code>/var/lib/nas-wizard-updates</code>, verifies its checksum, and runs its entry script
instead. This check does not use a token, which is entered later in the wizard. If the wizard
repository is private or networking is unavailable, for example before Wi-Fi setup, the check
reports the failure and continues with the packaged wizard.</p>
