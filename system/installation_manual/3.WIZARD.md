<h2 id="wizard">3. Guided setup</h2>

<p>The wizard listens on the machine's port 80. From another computer on the same network, open
<code>http://&lt;NAS-address&gt;/setup</code>, as printed by the entry script. Opening <code>/</code>
automatically redirects to <code>/setup</code>, preserving forwarded ports such as
<code>localhost:8080</code>. Until setup finishes, anyone who can reach the NAS can complete it,
just like a router's setup page. Complete it promptly on a trusted network.</p>

<h3 id="wizard_steps">1. Steps</h3>
<ol>
  <li><strong>Account</strong>: username and password for NAS sign-in. The same name, lowercased
  and with dots replaced by <code>_</code>, becomes the terminal user. It cannot be
  <code>nas</code>, <code>nas-os</code>, <code>root</code>, or an existing user.</li>
  <li><strong>Name, language, and theme</strong>: the NAS network name (default <code>nas</code>),
  containing up to 63 letters, digits, and hyphens. Language and theme changes apply immediately
  to the wizard. All values can be changed later in settings.</li>
  <li><strong>Wi-Fi</strong>: optional with a wired connection. A connection is required before
  continuing because the wizard downloads the gateway and launcher from GitHub.</li>
  <li><strong>Data disks</strong>, when enabled: optionally initialize empty disks, with or without
  encryption. Initialization erases their contents. Existing data disks are left unchanged.</li>
  <li><strong>Token</strong> for private GitHub releases: leave it empty for public repositories.
  Create a <em>fine-grained token</em> limited to the gateway, launcher, and private application
  repositories with only <strong>Contents: read-only</strong> permission. <em>Check</em> reports
  whether each repository's releases are readable, the token is refused, or permissions are missing.</li>
  <li><strong>Summary</strong>: review and confirm the choices.</li>
</ol>

<h3 id="wizard_installation">2. Installation</h3>
<p>After summary confirmation, the wizard runs <code>packages/post_wizard</code> with the supplied
token and displays each installation step:</p>
<ol>
  <li>Download the latest gateway (<code>ValerioGc/nas-gateway</code>) and launcher
  (<code>ValerioGc/nas-launcher</code>) releases and verify their published checksums.
  A missing or mismatched checksum is rejected.</li>
  <li>Install the gateway without starting it because the wizard still owns port 80.</li>
  <li>Install the launcher, which starts listening on loopback only.</li>
  <li>Store the encrypted token, create the terminal user, and prepare its data volumes
  (<code>ui_configuration</code>). Initialize empty disks only when explicitly selected.</li>
  <li>Create the username/password account in the gateway database and prepare the NAS CA for
  HTTPS without creating device certificates or enabling mTLS.</li>
  <li>Send the NAS name, language, and theme to the launcher. It applies the hostname and starts
  installing catalog applications marked for automatic system installation.</li>
  <li>Copy the installation manual and launcher user manual to the terminal user's home. Empty
  the extracted package directory, keeping only <code>uninstall.sh</code>, and remove the archive
  if it is adjacent to the directory.</li>
  <li>Offer the CA for installation as a trusted authority, then close the wizard and start the
  gateway on HTTP 80 and HTTPS 443.</li>
</ol>
<p>If a step fails, the wizard shows the latest log lines and a button to retry that step. Every
step is repeatable. If the wizard stops, rerun the entry script or, if the package directory has
already been emptied, run <code>sudo systemctl start nas-wizard</code>. Read the full log with
<code>journalctl -u nas-wizard</code>.</p>

<h3 id="wizard_handover">3. Handover to the NAS</h3>
<p>At completion, download the NAS CA for HTTPS. The sign-in button hands the ports to the gateway.
The page waits for it to respond and opens the NAS on the same origin, preserving protocol and
port. NAS preparation tracks system application installation before username/password sign-in.
Afterward, Security Center > Devices can create a browser certificate. Import it, reopen the NAS
over HTTPS, and enable mTLS with account-password confirmation. Activation requires the browser
to present a valid certificate already.</p>
<p>If the gateway does not respond, the wizard reclaims port 80 and shows the error with a retry
button. Downloaded installation files are removed. The installed wizard remains disabled in
<code>/usr/local/lib/nas-wizard</code>; a system-settings reset starts it again without deleting
data-disk files. The extracted package directory can be removed after installation.</p>

<h3 id="wizard_checks">4. Verification</h3>
<p>Both installed components provide checks that do not change the machine:</p>

```bash
sudo /usr/local/lib/nas-os/check.sh
sudo /usr/local/lib/nas-os-gateway/check.sh
```

<p>Each line reports <code>[OK]</code> or <code>[KO]</code> with a reason, followed by the number
of issues to resolve. The launcher listens only on loopback port 3000; the gateway serves HTTP 80
and HTTPS 443:</p>

```bash
systemctl status nas-os nas-os-gateway
journalctl -u nas-os -f
```
